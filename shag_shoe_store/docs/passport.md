# Паспорт проекта

## 1. Название проекта
Информационная система магазина обуви «Шаг».

## 2. Проблема
В магазине необходимо постоянно отслеживать актуальные остатки обуви на складах и поддерживать единый каталог товаров. При разрозненном хранении данных сотрудникам сложнее быстро находить товары, проверять наличие и корректно обрабатывать заказы.

## 3. Пользователи
- **Гость** — просматривает каталог товаров без поиска, фильтрации и сортировки.
- **Авторизованный клиент** — просматривает каталог товаров.
- **Менеджер** — ищет товары, сортирует и фильтрует каталог, просматривает заказы.
- **Администратор** — управляет товарами и заказами: просматривает, добавляет, редактирует и удаляет записи с учётом ограничений системы.

## 4. Цель проекта
Разработать информационную систему магазина обуви, которая обеспечивает централизованное хранение каталога, отображение актуальных остатков и разграничение функций пользователей по ролям.

## 5. Метрики успеха
- Поиск товара по текстовым полям каталога выполняется после изменения строки поиска без отдельного нажатия кнопки.
- Фильтрация по поставщику и сортировка по остатку применяются совместно с поиском и обновляют список в реальном времени.
- После добавления, редактирования или удаления товара каталог отображает актуальные данные из базы данных.
- При попытке удалить товар, который присутствует в заказе, система запрещает операцию и показывает сообщение пользователю.

## 6. Границы (что НЕ делаем)
- Не разрабатываем отдельное мобильное приложение.
- Не подключаем реальные платёжные сервисы и внешние службы доставки в рамках текущего описанного функционала.
- Не реализуем полный коммерческий интернет-магазин за пределами требований учебного задания.
- На текущем этапе репозиторий содержит документацию и блок-схемы; готовый программный код добавляется по мере выполнения следующих этапов.

## 7. Риски
- **Ошибки при переносе исходных данных** → проверять обязательные поля, кодировку и связи до импорта, после загрузки проверять результат.
- **Некорректные остатки или цены** → проверять вводимые значения и актуальность данных в базе.
- **Случайное удаление или изменение товара** → ограничить операции правами администратора, запрашивать подтверждение удаления и запрещать удаление товара, присутствующего в заказе.
- **Задержка выполнения этапов** → обновлять план Гантта в начале каждой пары и переносить незавершённые артефакты на следующую пару с честным статусом.
